# Помощник нефтяник РФ

Обновление от 9 сентября: [ЮKassa, группа загрузки и библиотека файлов](UPDATE_GUIDE.md). Для новых возможностей используйте эту инструкцию; разделы ниже описывают исходный запуск со Stars.

Telegram Mini App с каталогом учебных материалов. Оплата цифровых материалов — Telegram Stars. Решения и задания приходят документами в личный чат с ботом. Студенческий дизайн сохранён; админка доступна отдельно по /admin.

Пошагово для первого запуска: [SETUP_GUIDE.md](SETUP_GUIDE.md). Работа с оригиналами на Диске: [GOOGLE_DRIVE_GUIDE.md](GOOGLE_DRIVE_GUIDE.md).

## Что нужно подключить перед запуском

1. Создать постоянную PostgreSQL-базу. Для небольшого теста можно использовать Neon Free; для продаж выбирать тариф с достаточными лимитами и резервными копиями. База хранит покупки, очередь выдачи, каталог, файлы и права владельца. Сами документы хранятся в Telegram.
2. Заполнить переменные из .env.example в Render. Существующий .env автоматически не переписывается.
3. Указать BOT_TOKEN существующего бота, DATABASE_URL из панели PostgreSQL, APP_URL с HTTPS и TELEGRAM_WEBHOOK_SECRET (случайная строка от 32 символов из A–Z, a–z, 0–9, _ и -).
4. ADMIN_USERNAME уже настроен на AxmIldan. Первый подтверждённый Telegram-вход этого аккаунта закрепляет его числовой ID в базе. Лучше заранее задать ADMIN_CHAT_ID, если он известен. Имя без подписи Telegram доступ не даёт; после закрепления ID передача username другому человеку не передаст права.
5. В Render: Node.js 24, build command `npm ci --include=dev && npm run build:css`, start command `npm start`, health check /health.
6. Через BotFather настроить Mini App на APP_URL. Сервер сам регистрирует /telegram-webhook с секретом, сохраняя ожидающие обновления. Старый polling-процесс этого бота должен быть остановлен.
7. Написать /start боту из аккаунта @AxmIldan. Появится кнопка «Админка».
8. Отправить боту реальные документы как **файлы**. В админке открыть РГУНиГ → РФ и пройти по структуре до варианта. Назначить файлы и цену, включить выдачу и нажать «Сохранить вариант». ID создаются автоматически.
9. Прогнать реальные тестовые сценарии Telegram перед продажами: бесплатная выдача, отмена оплаты, оплата, заблокированный бот, повторная выдача, ответ поддержки, возврат.

Не используйте одну базу одновременно с разными ботами: file_id, права владельца и поддержка относятся к конкретному боту.

## Каталог и админка

catalog.json — начальный каталог. Изменения из админки хранятся в PostgreSQL и перекрывают начальные записи, переживая деплой. Каждая запись соответствует одному варианту. Названия курса, семестра, предмета и работы формируют прежнюю навигацию.

- telegramFileId — готовое решение.
- taskTelegramFileId — отдельный файл **условия**, доступный бесплатно.
- Если файла условия нет, «Ознакомиться с заданием» открывает прежнее окно описания.
- Для работы с несколькими вариантами кнопка ознакомления отправляет первый настроенный файл задания этой группы. Загружайте общий файл с условиями всех вариантов.
- priceStars — целое положительное количество Stars. Пустая цена отключает оплату. Старые рублёвые цены не пересчитываются автоматически.
- Отсутствующий файл отключает выдачу; пользователь видит «Скоро».
- Выключение материала запрещает новые выдачи/покупки; ранее оплаченное можно получить снова.
- Админка показывает последние 100 заказов, число попыток отправки, повторную выдачу и полный возврат Stars.
- После возврата повторная бесплатная выдача этой покупки отключается. Документ, уже сохранённый студентом, удалить с его устройства нельзя.

Существовавшие Google Drive URL сохранены только в локальном игнорируемом .legacy-catalog.json для ручного переноса. В рабочем каталоге их больше нет. Если старые ссылки уже были раскрыты, удаление из кода не отзовёт доступ к ним: пересмотрите общий доступ в Google Drive отдельно.

## Как работают оплата и выдача

1. Mini App отправляет подписанный Telegram initData, а сервер проверяет HMAC, срок (1 час) и ID пользователя. Переданный браузером chatId не используется.
2. Сервер берёт цену и файл из каталога. Оплаченные ранее работы повторно выдаются без нового счёта.
3. Создаётся заказ в PostgreSQL, затем счёт XTR через createInvoiceLink. В Mini App открывается стандартная оплата Telegram.
4. pre_checkout_query проверяет владельца, валюту, сумму и состояние заказа. Конкурирующие оплаты одного материала сериализуются блокировкой PostgreSQL.
5. Только successful_payment из защищённого webhook ставит оплаченный документ в очередь. Событие paid в браузере не разрешает выдачу.
6. Работник очереди вызывает sendDocument с сохранённым file_id. Сбой или 429 оставляет заказ в базе с отложенной повторной попыткой.
7. /purchases повторно отправляет последние 10 оплаченных материалов. Другие покупки можно запросить через каталог или поддержку.

Пустая очередь проверяется раз в 15 минут; новый запрос будит обработчик сразу. Не добавляйте частые запросы к базе только для «поддержания бодрости». /health проверяет процесс и не обращается к базе.

Доставка имеет семантику «как минимум один раз»: при обрыве между успешной отправкой Telegram и записью результата в PostgreSQL возможен второй экземпляр документа. У sendDocument нет ключа идемпотентности. Это предпочтительнее потери оплаченного материала. Повторная обработка обычного successful_payment сама по себе вторую выдачу не создаёт.

Счёт действует час. Если Telegram принял pre-checkout, но подтверждение оплаты потерялось, новый платёж за тот же материал временно блокируется до истечения окна; поддержка проверяет ситуацию, а не просит платить ещё раз.

## Поддержка

Студент пишет через существующее окно поддержки или напрямую боту. Бот отправляет вопрос владельцу. Владелец отвечает **ответом на сообщение бота** в личном чате, и бот доставляет ответ студенту. В миниаппе нет ложного обещания ответа через 10–15 минут; ответ приходит в чат. Поддерживаются текстовые обращения до 3000 символов.

Команды:
- /start — открыть каталог, владельцу также админку.
- /purchases — последние покупки.
- /support и /paysupport — помощь.
- /refund НОМЕР_ЗАКАЗА — полный возврат, только владельцу.

## Разработка и проверки

Node.js 24 рекомендуется (минимум 22). Установка: `npm ci`.
- `npm test` — тесты авторизации, HTTP API, SQL на PGlite, оплаты, очереди, поддержки, админки и DOM-интерфейса.
- `npm run check` — проверка синтаксиса.
- `npm run build:css` — сборка из закреплённой зависимости Tailwind.
- `npm audit` — актуальная проверка зависимостей.

Тесты используют временную PostgreSQL-совместимую среду PGlite и подмену Telegram API. Они не проводят платежи и не отправляют сообщения реальным пользователям. Проверка в настоящем Telegram и на целевом хостинге нужна отдельно.

## Переход со старой версии

Старые /create-payment, YooKassa /webhook и /download/:token возвращают 410. DOWNLOAD_TOKEN_TTL больше не используется. Новая интеграция ЮKassa использует отдельный /yookassa-webhook; настройка описана в UPDATE_GUIDE.md. Не переключайте работающий магазин с незавершёнными старым платежами вслепую: сначала остановите новые продажи в старой версии, проверьте платежи в кабинете YooKassa, выдайте недоставленные материалы либо верните оплату и сохраните старые записи. Автоматического доверенного импорта payments.json нет: старый webhook не проверял подлинность платежей.

Секреты не должны попадать в Git. Резервируйте PostgreSQL и оригиналы документов отдельно от Telegram. Перед продажами оформите собственные условия покупки, возвратов и обработки данных и проверьте доступность получения вознаграждений Stars для своего аккаунта.
