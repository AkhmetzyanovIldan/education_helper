## Что за токены были у скачивания

Это не криптовалюта и не Telegram Stars. Старый токен состоял из Base64 строки fileId|chatId|expiresAt и подписи HMAC-SHA256. Он служил временным пропуском к HTTP-скачиванию (обычно 15 минут).

Base64 ничего не шифрует. Подпись защищала от изменения содержимого, но не от пересылки ссылки другому человеку: получатель запроса не сверялся с chatId. Токен помечался использованным **до** успешного получения файла из Drive, поэтому сбой скачивания мог лишить покупателя доступа. Более того, прямые URL были доступны в API каталога, обходя токены полностью.

Теперь download-токены не нужны. Telegram file_id — идентификатор уже загруженного документа конкретного бота. Он хранится на сервере и используется только после проверки права на выдачу.

## Оплата

Внутри Telegram цифровые товары должны оплачиваться исключительно Stars (XTR); YooKassa/ЮMoney/СБП не являются альтернативной оплатой этих файлов внутри Mini App. Используется встроенный счёт Telegram с выдачей после successful_payment. [Документация Telegram](https://core.telegram.org/bots/payments-stars).

Рублёвая цена не равна количеству Stars: владелец назначает priceStars отдельно. Telegram указывает вознаграждение $0.013 за Star, возможное ожидание до 21 дня и получение через Fragment. Доступность зависит от пользователя/страны; цена покупки Stars студентом и ваш доход различаются. Это нужно проверить до назначения цен и начала продаж. [Условия разработчиков](https://telegram.org/tos/bot-developers#6-2-4-rewards-for-stars).

Вывод по проекту: для этой Mini App выбран Stars. Отдельный веб-магазин вне Telegram потребовал бы отдельного проектирования оплаты и проверки требований, а не перенаправления из этой Mini App на старую кассу.

## Файлы любого формата

Рекомендуемый путь: владелец отправляет исходный документ боту как файл, выбирает его в админке, бот повторно отправляет его по file_id. PDF, DOCX, XLSX, ZIP и другие форматы не требуют разных сценариев в приложении. Возможность открыть конкретный формат зависит от программ на устройстве студента.

Облачный Bot API ограничивает новую multipart-загрузку документа 50 МБ. URL-загрузка имеет меньший лимит и для sendDocument гарантирует только PDF/ZIP; Google Drive URL поэтому не используется как механизм выдачи. Документация отдельно разрешает повторную отправку существующих файлов по file_id без этих лимитов; ID привязан к одному боту. Фото необходимо загружать как документ, поскольку тип file_id при повторной отправке изменить нельзя. Для особо крупных файлов проверьте полный путь загрузки своим Telegram-клиентом; локальный Bot API — отдельная инфраструктура. [Bot API: Sending files](https://core.telegram.org/bots/api#sending-files).

Сохраняйте оригиналы вне Telegram: это доставка, а не ваша единственная резервная копия. Полученный документ студент сможет переслать; отказ от браузерных ссылок не является DRM.

## Проверки и оставшиеся ограничения

Итог: 19 тестов пройдены, сборка CSS и проверка синтаксиса успешны; npm audit не обнаружил известных уязвимостей на момент проверки.

Проверены подпись, срок initData, чужие заказы, отсутствие прямых ссылок, фальшивый webhook, сумма/валюта/покупатель, повторные события оплаты, отправка после сбоя, бесплатные задания, закрепление администратора, редактирование каталога, поддержка, возврат, XSS в каталоге. SQL запускается на PostgreSQL-движке PGlite; Telegram API подменён. Студенческая навигация и окно описания дополнительно открыты в браузере.

- Реальные списания, Telegram на Android/iOS/Desktop и целевая PostgreSQL пока не проверены: база и загруженные документы отсутствуют.
- Между Telegram sendDocument и записью в БД нет распределённой транзакции: после аварии возможен дубль файла, но повторная оплата не требуется.
- Вопросы/ответы поддержки не имеют полной очереди с гарантией единственной отправки: при повторе webhook после сетевого сбоя возможен дубль сообщения.
- Нет автоматической сверки истории Telegram Stars после длительной недоступности webhook. Не допускайте многодневного простоя; при расхождениях проверяйте транзакции бота и заказы.
- После смены бота надо заново загрузить файлы. После потери базы теряются покупки и закрепление владельца, поэтому резервная копия обязательна.
- Первый вход по username безопасен только пока @AxmIldan принадлежит вам; для строгой привязки до первого запуска задайте ADMIN_CHAT_ID.
- Старые незавершённые YooKassa-платежи требуют ручной сверки; новая версия намеренно не доверяет старому неподписанному webhook.
